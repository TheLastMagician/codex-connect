# Codex 连接

通过飞书或微信 ClawBot 私聊控制本机 Codex 桌面会话。飞书使用原生卡片和按钮；微信使用有编号、页码和下一步提示的文字列表。两个通道可以同时运行，分别保存选中的会话。
微信回复按选择确认、发送确认、状态和助手正文分别排版，使用清楚的段落与简短操作提示；列表使用显式换行，避免 ClawBot 把标题、状态和指令挤在同一段。长代码回复分段时保留代码围栏。当前公开协议没有飞书式交互卡片消息类型。
使用正在运行的桌面 App 的会话接口，操作原有会话，保留其模型、插件、项目和执行环境。
这是实验性版本，当前适配 Windows Codex 桌面 26.1007.2314.0；其他平台尚未实机验证。

0.5.0 新增本机通道管理页面：原有飞书、微信和多个飞书机器人都可在页面配置，保存后自动应用。新增飞书机器人可以选择“完整管理”或“固定会话聊天”；固定机器人只有文字聊天，所有输入（包括斜杠开头的文字）都发给本机指定的会话，没有插件管理命令或菜单。

0.4.4 修复桌面重启后仍连接旧管道的 ENOENT：连接失败时先验证最新保存的绑定；Windows 上还会从系统已发布的管道中核对服务端进程是否属于已注册的 Codex 桌面，再验证 Codex 会话工具目录和只读查询。保留宿主提供的真实调用会话，不猜测管道名、不创建替代 agent。桌面断开期间通道保持运行，后台继续等待恢复；已提交但结果未知的操作不自动重发。

0.4.3 简化聊天：选择、新建或复制会话后，直接发消息即可继续该会话，不再需要“进入直聊”。飞书按钮、回复编号、`/use` 和操作助手代选行为一致。已有选中会话自动使用这条规则；`/assistant` 保留为操作助手入口。

0.4.2 已取消 0.4.1 引入的新建自动全局 Responses 转发，保留供应商原有直连。第三方新建首条的兼容问题仍未实现仅针对新会话的修复，详见供应商直连与旧版兼容恢复。

0.4.0 新增可选自动连接：首次开启并信任本机启动钩子后，在 Codex 启动或恢复桌面会话时自动运行桥接，并更新桌面连接。无需每次手动启动，不调用模型、不发送任务；多会话同时恢复也只启动一个桥接。

0.3.8 支持直接发送到尚未加载的会话：飞书、微信直聊或操作助手转交任务时，插件自动在桌面打开未加载的目标，等待其连接就绪后，再通过普通用户消息入口发送原文。**这会切换当前桌面页面；已加载的会话仍在后台接收消息。** 打开失败或等待加载超时时明确提示消息未发送；结果未知的发送不会自动重试。无需改配置或重新配对。已完成模拟回归测试，实机收发仍由用户验证。

继续保留 0.3.7 对 `User-message admission requires a cloud app-server host` 的修复，不再强制使用云端消息入口；并保留 0.3.5 引入的普通用户消息入口，避免第三方 Responses 接口拒绝跨会话转交消息缺少 `call_id` 的情况。默认沿用目标会话的供应商、模型和权限；第三方供应商的实机收发验证待用户完成。

## 安装与配置

需要 Node.js 20 或以上及正在运行、已登录的 Codex 桌面版。本机完整历史列表还使用 Python 3 的标准库，只读打开桌面会话数据库，请在目标机器安装 Python 3。可用 `FEISHU_CODEX_PYTHON` 指定解释器。Python 不可用时会明确提示列表不完整。
包内 `dist` 已包含运行依赖，安装后无需 npm install。

通过 GitHub 仓库安装的方法见[仓库安装说明](https://github.com/TheLastMagician/codex-connect#在另一台机器安装)。每台机器需要分别扫码或配置飞书凭据；这些授权信息不包含在插件中。

### 本机管理页面（推荐）

插件 MCP 服务加载时会自动启动管理页面服务，不会自动弹出浏览器。首次在 Codex 中说“打开 Codex 连接配置页面”，调用 `open_settings` 后打开返回的链接。也可在插件目录运行 `node dist/setup.cjs dashboard` 获取本机访问链接。通常地址为 `http://127.0.0.1:32147/`；端口被占用时自动选择可用端口，并记住该地址。

首次链接包含本机访问授权，浏览器进入后会移除地址中的授权片段。可以收藏清理后的页面地址。其他浏览器需重新通过插件打开，勿分享带授权片段的链接。服务仅监听本机，不需要公网地址。

- **原来的飞书**：主机器人自动读取现有凭据、配对和选中会话；编辑时 Secret 留空可保留。
- **添加飞书机器人**：填写名称、App ID、App Secret，选择完整管理或固定会话。相同 App ID 不能重复连接。
- **绑定会话**：从真实 Codex 项目和会话列表中选择，可按标题搜索。本机历史会话完整加载，远程主机仅列最近会话；桌面不可用时已有绑定可保留。
- **允许使用**：新应用的用户 ID 与主应用不同。首次私聊机器人后，在页面“使用申请”中点允许，再重新发消息。首次消息只用于申请，不自动执行；固定机器人无需发送配对命令。原来的配对账号继续有效。
- **微信**：页面扫码、刷新二维码、填写验证码、暂停或断开连接。现有登录会自动保留。

每个飞书机器人的选择、模型覆盖、消息去重和回复通知分别保存。固定机器人的目标只能在本机页面修改，沿用绑定会话的桌面模型、供应商和权限。固定模式没有 `/help`、`/chats`、`/assistant` 等插件操作，这些文字也作为任务原文发送。停用、删除或改绑会阻止旧连接继续派发排队任务，但不会停止已进入 Codex 的任务。

页面中的配置与会话目录查询由程序执行，不调用模型。通道发送真实任务后仍使用 Codex 会话本身的模型用量。

页面随桥接后台进程运行。`stop_bridge` 会停止页面和通道；重新调用 `open_settings` 可打开页面，聊天通道仍保持本次暂停，直到在页面点恢复连接或手动启动桥接。启用桌面启动钩子仍需按 Codex 要求审阅信任。

### 微信 ClawBot

无需 App ID、App Secret 或公网回调地址。使用腾讯公开的 iLink 协议，独立连接 Codex；不需要安装 OpenClaw。

1. 在 Codex 中说“连接微信”。插件 `wechat_login` 返回本地二维码图片路径；用手机微信扫一扫，并在手机确认。
2. 如果状态为 `need_verifycode`，将手机显示的配对验证码交给 `wechat_verify_code` 提交。后台最多等待 5 分钟，二维码可被微信服务器提前标记过期；过期后用 `wechat_login(refresh=true)` 刷新。
3. 使用 `wechat_login_status` 查看登录状态，`bridge_status` 查看通道状态。扫码凭据保存到本机受限目录。登录成功后，桥接自动启用微信，只接受扫码账号发来的私聊指令。
4. 在微信 ClawBot 聊天中发送 `/help` 或 `/projects`。回复项目编号查看会话，再回复会话编号选择；选中后直接发消息，就是与该 Codex 会话聊天。
5. 用“下一页”“上一页”、`/page 2` 翻页；`选择 12` 或 `/use 12` 选择会话。`/chats 关键词` 可按标题查找。

微信与飞书的会话选择、去重、回复上下文和关注通知分别保存。重连不会重新执行已接收的任务。回复会回传最新微信消息的 `context_token`；只处理当前消息文字，引用内容不会当成新任务。

微信第一版支持文字。图片、文件、语音会收到转换为文字的提示；不支持群聊和飞书式卡片按钮。停止任务及执行审批仍需在 Codex 桌面处理。调用 `disconnect_wechat` 可断开微信，飞书继续运行。断开后可再次扫码换绑。QQ、企业微信属于后续通道，目前未实现。

### 飞书

1. 通过 GitHub 仓库插件源安装，或安装本地插件包。
2. 飞书开放平台使用**自建应用机器人**，不是群 Webhook 自定义机器人。
3. 启用机器人能力；开通 `im:message.p2p_msg:readonly`（获取用户发给机器人的单聊消息）和 `im:message:send_as_bot`（以应用身份发送消息）。权限名称以后台显示为准。
4. 事件与回调订阅 `im.message.receive_v1`，选择**长连接**接收事件。
5. 在版本管理与发布中发布应用，将自己的账号纳入可用范围。事件方式配置可能要求先启动桥接再保存。
6. 运行 `setup.cmd`，填写 App ID、App Secret。已经配置过可回车保留。
7. 在 Codex 桌面聊天里说“启动飞书桌面桥接”。插件技能会先运行只读的 `src/bind-desktop.mjs` 绑定真实桌面上下文，再调用 `desktop_probe`、`start_bridge`，并用 `bridge_status` 核对 `feishuState: connected`。
8. 在飞书私聊机器人，发送配置程序显示的 `/pair 配对码`。有效期 10 分钟，一次成功后销毁。以后无需再次输入凭据。

要使用卡片按钮，在飞书后台的事件与回调中添加 **卡片回传交互 `card.action.trigger`**，选择长连接并发布生效。
确认开启后，让 Codex 调用 `configure_card_actions(enabled=true)`。不启用按钮时仍显示原生卡片，使用文字命令操作。
现有账户的卡片按钮设置会在修改凭据时保留，不需要重新配对。

配置仅存于当前用户的 `~/.codex-feishu-desktop/config.json`，Windows 目录限制为当前用户可访问；不打包上传。
配对后的飞书账号可以操作桌面可访问的 Codex 会话。其他账号、群消息、过旧或重复事件不会执行任务。

```text
/chats

/use 3
帮我检查这个项目的启动错误
/read
/status
/projects
/project 1
/new 1 | 检查这个项目的构建
/new - | 帮我整理一个待办清单
/rename 修复启动错误
/pin
/archive
/archived
/next
/use 1
/unarchive
/watch
/unwatch
/open
/help
```

每个列表回复都会带当前页数、具体选择示例与可用翻页命令。`/next` 或 `/more` 下一页，`/prev` 上一页，`/page 2` 跳页。
卡片上也可以直接点击「查看」「选择」「上一页」「下一页」。按钮操作更新原卡片，避免连续刷屏。
列表只显示项目名称和短目录；查看完整目录可打开项目后点击「项目详情」，或发送 `/projectinfo 1`。
对话回复、当前状态、错误、帮助和通知也使用原生卡片；长回复按段发送，并保持代码块的格式。
按钮绑定到真实项目/会话 ID、当前配对用户和原私聊，旧编号变化不会误选其他会话。
也可以直接说“下一页”或“上一页”。编号在同一份列表内跨页固定，第 2 页从 11 开始。
列表出现后直接回复编号即可选择：会话列表选中会话，项目列表查看该项目的已有会话。
选中会话后，普通文字和纯数字都直接发给该 Codex 会话，不会再次当作选择编号，也不经过操作助手。
`/projects` 也会提示 `/new 1 | 任务内容` 的新建方法；`/project 1` 仅查看该项目的已有会话，不创建任务。
归档列表按桌面返回的翻页信息加载，支持前后查看已加载页；到最后一页会明确提示，不会重新从第一页开始。
选择归档会话后，先 `/unarchive` 恢复，再聊天。

编号来自你上次请求的列表，不会因另一个人的列表或通知重新编号。同名会话用编号区分。
本机普通会话从桌面的本地目录完整加载，包括最近 50 条之外的历史；每页 10 条，点击“下一页”或 `/next` 翻页。项目归属使用桌面已保存的分配及目录信息。数据库使用 SQLite 只读连接，发送、创建及修改仍通过桌面真实接口执行。远程主机目前只显示最近会话，卡片会说明这一范围。
后台通知使用 `read_thread`，不依赖当前聊天的活动轮次；不会因 `wait_threads` 的轮次限制而阻止发送。发送结果未知时不会自动重试，卡片会提示先检查会话。
列表底部显示当前发送目标。选中、创建、发送、通知、错误、归档等回复也会附带下一步操作提示。
`/send 原任务内容` 可直接转交任务，包括以 `/` 开头的内容。选择会话后，普通消息直接继续所选 Codex 会话；尚未选择时，普通消息交给操作助手。`/assistant` 可随时打开操作助手。
切换会话后，之前任务的通知仍带原会话标题。飞书事件立即确认，不等待 Codex 执行。

## 本机进程与诊断

### 供应商直连与旧版兼容恢复

0.4.2 已取消新建会话时自动启用全局 Responses 转发。新建及已有会话均使用桌面原有连接，插件不修改供应商 `base_url`、模型、API Key 或桌面配置。全局兼容不再支持开启；下面的工具和程序仅用于恢复 0.4.1 已修改的地址。

**第三方 Responses 的新建首条 `call_id` 问题尚未实现仅针对新会话的兼容。** 桌面原生新建接口可能把首条任务作为缺少 `call_id` 的转交记录；严格校验的供应商会拒绝它。这条记录还可能留在历史中，使后续请求再次失败。因此，不能只代理创建时的一次请求再恢复直连。当前新建接口没有公开单独指定会话供应商或接口地址的参数。

如果该供应商在插件新建时遇到这个问题，可以先在桌面手动新建并对话，再从飞书或微信选择这个会话继续。插件不会因此自动启用全局代理、重发失败任务或修改旧历史。正常已有会话仍沿用桌面用户输入路径。

调用 `responses_compat_status` 检查是否有旧版全局兼容。若已启用，调用 `configure_responses_compat(providerId="返回的真实ID", enabled=false)`，或在插件目录执行：

```powershell
node dist/setup.cjs compat status
node dist/setup.cjs compat off custom
```

恢复会先把供应商地址还原，再停止对应转发；不会覆盖用户在插件外重新设置的地址。完成后请重启 Codex，使已经加载的配置也恢复。没有启用过兼容时，不需要为此重启。

旧版兼容服务在地址恢复前仍会保持运行，避免供应商地址指向已停止的服务。卸载前应先恢复；若已卸载，可执行本机保留的恢复程序（需要 Node.js 和 Python 3.11+）：

```powershell
node "$env:USERPROFILE/.codex-feishu-desktop/runtime/responses-compat-daemon.cjs" restore
```

桥接是后台本机进程，单实例，关闭发起聊天不影响已启动的桥接。关闭桌面 App 会使桌面会话接口失效。
自动连接开启后，桌面重新启动或更新并恢复会话时重新绑定真实桌面连接；已有桥接会验证实际查询是否可用，后台接入新连接，不重发之前的任务。Windows 自动发现需要系统自带的 PowerShell，并校验已注册的 Codex 包及管道所属进程；其他平台目前依赖最新宿主绑定。未开启自动连接时，在任意桌面聊天重新绑定并调用 `start_bridge`。
桥接失败不会启动独立 CLI 作为替代。未收到飞书消息时，检查应用是否发布、可用范围、事件和消息权限。
`bridge_status` 不返回 App Secret；`bridge.log` 不记录 SDK 请求或凭据。
桌面接口是该版本内置 app-tools 的本地协议，不是承诺稳定的第三方远控 API，更新后可能需要适配。

### 自动连接设置

在 Codex 中调用 `configure_autostart(enabled=true)`，或在插件目录执行：

```powershell
node dist/setup.cjs autostart on
```

它在当前用户的 Codex `hooks.json` 注册 `SessionStart` 启动／恢复钩子，保留其他钩子；运行组件保存在本机受限数据目录中，不依赖发起聊天一直打开。首次在 Codex **设置 → Hooks／钩子** 中审阅并信任“连接 Codex 桌面聊天通道”；CLI 可用 `/hooks`。插件不会改写信任记录，也不会关闭钩子审阅。参见[官方信任说明](https://learn.chatgpt.com/docs/hooks#review-and-trust-hooks)。

启用后，在桌面启动或恢复会话时自动启动已配置通道。插件 MCP 服务加载时也会检查是否需要连接。尚未加载任何会话的空白首页不保证触发钩子；需要 Node.js 20+、已配置通道和真实桌面提供的连接信息。独立 CLI 触发钩子时，不会把它的会话冒充成桌面调用来源。

`bridge_status.autostart` 显示开关、钩子是否注册、当前桌面是否手动暂停及最近启动检查状态。注册成功不等于已信任，仍需在 Codex 审阅一次。通道 `connected` 才表示连接成功。

手动 `stop_bridge` 后，本次桌面运行期间不会被后续会话再次拉起；重启 Codex 或手动 `start_bridge` 恢复。永久关闭用 `configure_autostart(enabled=false)` 或 `node dist/setup.cjs autostart off`，仅移除本插件注册的钩子并关闭开关，不停止当前桥接、不删除凭据和配对。

## 查看最近对话

在飞书点击「查看对话」或发送 `/read`，读取所选真实桌面会话的最近三轮对话，按从旧到新排列。包括你的消息、Codex 的进度消息和最终回复；每条消息以「你 / Codex」及消息编号标识，并使用原生分隔线区分。Markdown 和代码块保留，长内容分卡片并标明续接。

这里显示的是近期上下文，不是全部历史。消息数量过多时会明确提示省略较早内容，完整上下文可在 Codex 桌面查看。附件显示占位提示，内部推理和工具执行详情不展示。自动回复通知仍只发送新任务的最终回复；`/status` 仅显示状态。

## 模型管理与操作助手（0.3.6）

在飞书或微信发送 `/models` 查看本机可用模型及支持的推理强度。飞书也可点击模型卡片的「使用」按钮。命令：

```text
/model
/model gpt-6.1-sol
/effort xhigh
/effort default
/model default
/assistant
/assistant 帮我找到订单项目里排查订单失败的会话并选中

```

`/model` 查看覆盖设置；`/model 模型ID` 或 `/model 编号` 为当前会话设置模型，`/effort` 设置强度。无效模型或该模型不支持的强度不会替换原设置。
设置按通道、控制账号、目标主机和会话分别保存。它们作为 `send_message_to_thread` 的 `model` / `thinking` 参数传入后续任务，选择模型本身不会开始任务。未指定时不传覆盖参数，沿用桌面会话设置。
`/model default` 同时清除模型和强度覆盖；`/effort default` 只清除强度覆盖。当前接口不返回继承设置的具体模型 ID，显示“沿用桌面会话设置”；不能据此断言桌面上的永久选择已经改变。
目录来自当前本机的真实桌面工具说明。远程主机模型可能不同，发送时由目标主机校验。

操作助手是独立的模型接口，可帮助查找项目和会话、选择目标、查看模型、改名、置顶、归档、查看状态，以及按用户明确要求新建任务。
在 Codex 桌面聊天中让插件调用 `configure_assistant`，配置 `baseUrl`、`model`、`apiKey`、可选 `reasoningEffort`；也可在插件目录执行 `node dist/setup.cjs assistant`，在本机隐藏输入 Key。`assistant_status` 查看不含凭据的配置。
当前支持 OpenAI 兼容的 Chat Completions 工具调用协议（`/chat/completions`、`tools`、`tool_calls`）；配置的模型须支持此协议和相应的推理强度参数。提供商错误不会自动重试或自动切换模型。

尚未选择会话时，普通消息由操作助手处理。通过编号、`/use`、飞书按钮或助手代选，选中后直接发消息就是与该 Codex 会话聊天；新建、复制会话后也直接继续所选会话。使用该会话模型或当前覆盖，不再需要额外进入直聊。
需要操作助手时，发送 `/assistant`，或说“操作助手”“返回助手”“切换会话”。`/assistant 指令` 可直接管理；重新选择会话即恢复与该会话聊天。旧 `/resume` 命令和旧卡片回调仅为兼容保留，不再出现在新卡片和帮助步骤中。
升级到 0.4.3 后，已有选中会话直接接收后续普通消息，保留目标、模型覆盖和助手历史。升级后再主动打开的助手状态会在重启后保留；再次选择会话后直接聊天。
操作助手可代操作插件已支持的全部管理命令，包括复制会话、通知开关、归档列表、项目详情和分页。“进去会话”“到那个会话接着聊”等表达通过查询并选择目标完成，不需要再切换聊天模式。身份仍由配对账号校验，目标必须来自真实目录，任务内容必须来自本次用户消息。停止任务和执行审批仍需在桌面处理。
助手查询后的项目/会话列表仍可回复编号、翻页或点击按钮。多项匹配时需要继续选择。助手不能运行任意 shell、读取配置凭据或处理桌面执行审批。

助手请求只包含本次对话、有限的助手历史、项目和会话的名称/ID及相关管理结果；既有 Codex 回复由本机直接显示，不自动交给助手模型。项目名称和会话标题会发送到你配置的接口，按该提供商的数据政策处理。
固定命令和按钮的解析、查询、选择、读取及模型设置不调用助手模型；自然语言助手调用会消耗所配置接口的用量；新建或发送任务会使用 Codex 会话的模型用量。
凭据保存在本机受限目录 `~/.codex-feishu-desktop/assistant.json`，不会随仓库或 ZIP 分发。每台机器单独配置助手接口。
