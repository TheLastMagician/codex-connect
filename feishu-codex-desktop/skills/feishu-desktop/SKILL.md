0.7.0 管理型飞书与微信使用专用机器人的插件本机持久队列，按目标会话串行，上一条实际轮次结束后才发送下一条；桌面执行中或审批中也等待，不把后续消息变成引导。入队固定原目标、模型覆盖和来源；不同目标独立，管理命令不被冷加载阻塞，/status 显示等待数。各通道共用目标执行锁。队列原文保存在本机私有目录以支持重启恢复，不包含在发布包或 GitHub；未提交的 preparing 恢复排队，已发送或回执不确定只读核对，绝不盲目重发。/unwatch 仅关闭额外关注，不取消任务或逐条回复。取消“会话加载中”卡片，仍保留 2 分钟加载预算和同批消息最多打开一次。连接失败保留队列并等待恢复。不是 Codex 原生队列。不要发送实机测试任务，实机验证由用户完成。

0.6.2 冷会话自动打开后最多等待 2 分钟，等待期间仅打开一次，不发送加载进度卡片，真实连接就绪后才首次提交。不能在旧的 20 秒时限后就认定加载失败；历史加载、原生 thread/resume 完成与 stream owner 就绪可能不是同一时刻。授权撤销或最终超时均不提交。诊断须按原始失败时间对齐桌面日志；用户随后切换的配置、后续探测产生的错误不能用来解释之前的失败。未经用户明确要求，不改 Codex 供应商配置、预设、供应商地址或凭据。
0.6.1 回执核对优先使用真实轮次 ID 或客户端 ID。标准历史只返回规范消息编号时，联合发送前轮次、实际提交时间和带随机盐的完整原文摘要，唯一匹配新出现的真实轮次；存在重复歧义时继续核对，不猜测、不重发。摘要不保存原文；较早轮次可翻页查找。
0.6.0 已移除操作助手、其配置与状态工具、命令和按钮。不要再调用旧配置工具或建议设置单独模型接口。启动时清理旧助手凭据与管理历史；保留真实会话选择、模型覆盖和通道凭据。未选目标时引导用户用列表、编号、命令或卡片选择，不把普通消息交给额外模型。
0.5.7 起普通发送在写入前持久保存客户端消息 UUID；0.6.1 补充标准历史关联。回执异常按原目标只读核对，确认后返回原轮次回复；重启后继续，不改变当前选择。诊断 nativeReason 区分 request_timeout、start_timeout、connection_closed、router_rejected、native_error，不保存原始接口错误。0.7.0 起管理通道也复用固定机器人的持久队列。不要发送实机测试任务，实机验证由用户完成。
0.5.6 完整管理机器人发送前读取已选会话，短暂断连可自动只读重试一次；普通消息入口的连接/owner 发现同样最多只读重试一次。禁止把该重试用于真正任务发送或结果未知的修改。失败保留所选目标并明确无需重新选择。本机 profile 的 deliveryFailures 保留最近 20 条时间、阶段、原因及目标 ID，不记录提问正文、原始接口错误和凭据；卡片更新不得清除。bridge_status 的通道 lastDeliveryFailure 提供最近一条诊断，其中 retrying 表示该失败后是否尝试过只读恢复，不代表最终发送失败。不能仅凭用户模糊描述把短暂断连说成选择丢失；先核对诊断，无法确定时说明范围。
0.5.5 固定机器人连接重试时，同一批等待消息最多自动打开目标一次，标记随队列持久保存；后续重试不得重复导航或抢焦点。真正发送前，在等待加载完成后再读取一次空闲状态并复核授权，避免把排队消息插入刚开始的桌面任务。连接健康检查只轻量读取真实调用会话，不列举所有会话，不发送测试任务。

0.5.4 固定机器人仍使用插件本机队列，不是桌面原生队列；按目标会话串行执行，同一机器人的群聊和私聊共用，其他目标独立。每条请求保存客户端消息标识和原提问者，确认回执保留轮次 ID。发送结果未知或无法关联完成轮次不能等同于“会话仍在执行”。超过两分钟且连续至少 15 秒多次成功读取确认会话空闲后，将原消息保留为待核对，后续请求继续处理；不重发待核对的原消息、不把其他轮次的回复冒充其结果。执行中、审批中及读取失败时不能据此放行。后续关联到原消息的真实结果仍只回原聊天、@ 原提问者。待核对记录只保存在本机私有数据目录。
0.5.2 固定机器人使用无按钮的飞书原生卡片回复，渲染 Markdown 加粗、列表、行内代码和代码块；保留普通标点、数字和箭头，清理终端控制码。模型生成的 at 标签按文字转义，不触发通知。群聊卡片第一段只 @ 该条问题的真实提问者；名单持久化，撤销授权后不再 @ 该账号。私聊不额外 @。卡片没有管理按钮、项目列表、命令提示，不需要 card.action.trigger 回调；保留“跟随飞书应用范围”的访问方式。仅影响更新后的新回复，不重发或重写旧消息。实际排版与 @ 通知由用户在飞书实测，不自动发送测试任务。
0.5.1 支持飞书普通群的文字 @：通过当前应用 /bot/v3/info 核验真实机器人 open_id，仅处理确实 @ 该机器人的消息，移除机器人 @ 占位符，其他用户 @ 保留为可读文字。未 @、@其他人、@所有人、机器人回声都不触发。飞书后台需开通“获取群组中 @ 机器人的消息／接收群聊中 @ 机器人消息事件”权限，保留 im.message.receive_v1 长连接订阅和发送消息权限，并发布应用生效。无需公网回调地址，也无需读全群聊天权限。groupMentionReady 状态表示已取得机器人身份，不表示平台群消息权限已发布。
固定机器人群内 `@机器人 问题` 直接发给绑定会话，回复发回原群，仍无插件命令或菜单；所有已授权成员共用绑定会话的上下文，每条问题分别回复原提问者。完整管理机器人在群中先 `@机器人 /chats` 选择，选择按群和账号隔离，不自动复制私聊选择。按钮继续绑定原账号、原聊天和原卡片。群内普通消息也必须 @；单独 @ 只回本地用法提示，不调用模型。固定模式可选 accessMode=feishu（跟随飞书应用范围），此时接收到的人类私聊或群内 @ 无需本机批准，范围由飞书可用范围和群管理控制，不自动添加本机账号名单；完整管理型不能使用此方式。accessMode=approved 或旧版未设置时，首次未授权私聊/群 @ 记为本机使用申请，批准后重新发送。不在群里使用或消费 /pair 配对码。当前不单独适配话题群线程。
0.5.0 推荐使用 `open_settings` 获取本机通道管理页面，并用浏览器打开返回的完整 URL（授权片段仅给本机用户，不公开分享）。插件 MCP 加载时页面服务自动启动，不自动弹窗；缺少桌面连接时仍可配置，不能声称此时能发送任务。页面通常监听 127.0.0.1:32147，占用时自动选端口。首次打开后授权转入 HttpOnly Cookie，页面地址会清理授权片段，可收藏清理后的地址。
页面可编辑主飞书、添加/停用/删除其他机器人、从真实目录绑定固定会话、批准使用申请，以及微信扫码和断开。原有凭据、配对、会话选择保留；Secret 留空保留。新应用用户 ID 独立，用户需先私聊新机器人，再在本机页面批准申请，之后重新发送任务；首次申请不自动执行。固定机器人可选择跟随飞书应用范围，免本机逐个批准；仅本机批准模式和完整管理型仍使用申请或配对。固定模式不提供插件命令或管理按钮，所有消息（包括 /xxx、编号）都是发给绑定会话的原文；只在本机页面改绑。完整管理模式保留原有命令和按钮。不要在固定机器人里提示 /pair 或 /chats。
页面配置不调用模型，不需要每新增一个机器人都让助手手工改文件。`node dist/setup.cjs dashboard` 也可获取入口。stop_bridge 停止后台进程和页面；open_settings 可恢复页面但保留本次聊天暂停，页面“恢复连接”或 start_bridge 才恢复聊天。已启用的通道随插件 MCP 加载连接；configure_autostart 另外提供桌面会话钩子触发的连接。
