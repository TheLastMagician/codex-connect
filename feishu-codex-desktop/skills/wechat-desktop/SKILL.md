0.7.0 管理型飞书与微信使用专用机器人的插件本机持久队列，按目标会话串行，上一条实际轮次结束后才发送下一条；桌面执行中或审批中也等待，不把后续消息变成引导。入队固定原目标、模型覆盖和来源；不同目标独立，管理命令不被冷加载阻塞，/status 显示等待数。各通道共用目标执行锁。队列原文保存在本机私有目录以支持重启恢复，不包含在发布包或 GitHub；未提交的 preparing 恢复排队，已发送或回执不确定只读核对，绝不盲目重发。/unwatch 仅关闭额外关注，不取消任务或逐条回复。取消“会话加载中”卡片，仍保留 2 分钟加载预算和同批消息最多打开一次。连接失败保留队列并等待恢复。不是 Codex 原生队列。不要发送实机测试任务，实机验证由用户完成。

0.6.2 冷会话自动打开后最多等待 2 分钟，等待期间不发送加载进度卡片，真实连接就绪后才首次提交。每次等待只打开一次，已加载目标在后台发送；最终超时或授权撤销不提交。诊断按原始失败时间对齐桌面日志，不用后来切换的配置或后续探测错误解释之前失败；未经用户明确要求，不改 Codex 供应商配置及预设。

0.5.0 可用 `open_settings` 打开本机管理页面，在页面扫码、刷新、输入验证码、暂停或断开微信，原有登录自动保留；不需要每次让助手生成二维码。页面服务随插件 MCP 加载启动，不自动弹窗；仅在本机访问。首次打开返回的完整链接，进入后会自动清理授权片段，可以收藏清理后的地址；不要把带授权片段的链接公开分享。页面扫码本身不要求先连接桌面，真正控制会话仍需要有效的真实桌面连接。插件加载也会连接已启用通道，启动钩子提供额外的桌面会话触发。stop_bridge 也会停止管理页面；open_settings 可恢复页面但保留本次聊天暂停，可在页面点恢复连接。

新建与已有会话均使用桌面原有供应商连接，不自动修改 base_url 或启用全局兼容。第三方 Responses 新建首条缺少 call_id 的问题尚未实现仅针对新会话的兼容；遇到时可由用户先在桌面新建，再选择该会话继续。不能声称已修复，不自动重发或修改历史。responses_compat_status 可检查 0.4.1 遗留的全局兼容；configure_responses_compat 仅支持 enabled=false 恢复原地址，之后提示重启 Codex。未启用过不需要重启，禁止重新开启全局代理。不要索取或打印 API Key。

用户明确要求连接微信时，使用本插件的 `wechat_login`。这是微信 ClawBot 的扫码连接，使用腾讯公开 iLink 协议。
调用需要真实 Codex 桌面上下文。缺少绑定时，先在当前桌面会话终端执行插件的 `src/bind-desktop.mjs`，不得猜测管道或伪造其他会话。
返回 `qrPath` 后，用绝对路径图片展示二维码，提示用户用手机微信扫一扫并在手机确认。二维码由服务端登录内容本地编码，不用图片生成模型，也不要把二维码或授权凭据发布到外部服务。
登录后台最多等待五分钟，微信服务可能更早让二维码过期，以 `wechat_login_status` 状态为准；避免频繁轮询。
`need_verifycode` 时仅在用户提供手机显示的配对验证码后调用 `wechat_verify_code`；不要猜测验证码。
过期或用户要求刷新、换绑时调用 `wechat_login(refresh=true)`。已有正常连接时不重复扫码。
登录确认后，`bridge_status` 的微信通道为 `connected` 才说明消息轮询已经连接。桥接运行时会自动载入新凭据。
如果桥接没有运行，使用 `start_bridge` 启动，再检查状态。仅配置微信即可启动，不要求飞书 App ID / Secret。
用户要求自动连接时使用 configure_autostart(enabled=true)；先在 Codex 设置的钩子页信任一次本插件注册的 SessionStart 钩子，CLI 可用 /hooks。不要代写信任记录。启用后，启动/恢复桌面会话或加载插件 MCP 时检查并连接已配置通道，多会话不重复启动；未加载会话的空白首页不保证触发钩子。bridge_status.autostart 可查看开关及注册状态，已注册不等于已信任。

引导用户使用 /help、/projects 或 /chats，再回复项目和会话编号选择目标。选中后直接发消息，就是与所选 Codex 会话聊天。
支持“下一页”“上一页”、`/page 2`、`选择 12` 和 `/use 12`。回复必须给出当前页数、全局编号和具体的下一步示例。
已有会话保持原模型、项目和上下文；微信、飞书分别保存选中的会话，桌面切换窗口不改变通道的发送目标。
扫码用户身份来自微信登录结果。只允许该账号的私聊控制，不自动授权陌生人、群消息或任何账号发出的 `/pair`。
机器人回声、引用内容和附件不作为新任务。第一版仅支持文字，附件需提示改发文字。
发送或创建结果未知时不要自动重试；先检查真实桌面会话是否已收到消息。

只在用户要求退出或断开微信时使用 `disconnect_wechat`；飞书通道保持运行。
`stop_bridge` 会停止所有通道的桥接，Codex 会话本身继续运行；本次桌面运行期间暂停自动拉起，重启 Codex 或手动 start_bridge 恢复。configure_autostart(enabled=false) 永久关闭自启动，仅取消本插件的钩子，不停止当前桥接或删除凭据。
凭据和回复上下文存于用户目录 `.codex-feishu-desktop` 的受限本机文件，不打印 token、不放入插件包、不提交 Git。
模型管理使用 `/models`、`/model 模型ID`、`/effort high`；`/model default` 恢复沿用桌面会话模型和强度。
设置按微信账号、通道、主机和会话保存，作为后续任务发送参数，不启动任务，也不保证改变桌面永久配置。
0.6.0 已移除操作助手及其单独模型接口、配置工具、命令和入口。未选会话时，普通文字只提示先选择；选择、新建或复制后直接发给对应 Codex 会话。升级启动时清理旧助手凭据与管理历史，保留微信登录、已选目标、模型覆盖和回复关注。不建议设置额外模型接口。
继续已有会话通过当前运行桌面 App 的协调 IPC 提交普通用户文字，继承目标会话的供应商、模型和权限。已加载的目标在后台接收消息；未加载时，桥接自动调用桌面导航打开目标，等待其真实会话连接就绪后再发送。这会切换本机当前桌面页面，无需用户手动点击；/open 仍可主动打开所选会话。加载超时或打开失败时明确提示消息未发送。自动打开前和发送前均检查微信账号授权，结果未知不重试，也不回退到跨会话工具结果。此入口不提供执行审批或停止任务，不启动另一个 app-server。
创建、修改和回复读取仍通过真实桌面 app-tools 管道；完整本机列表可只读查询桌面元数据，禁止修改数据库。
当前不能代点执行审批或停止桌面任务。不要用 shell、桌面代码修改或独立 CLI 会话绕过这些限制，也不要声称已经实现 QQ、企业微信或所有桌面功能。

桌面连接失效时，0.4.4 会先验证最新的真实绑定；Windows 会枚举系统已发布的连接，校验服务端进程属于已注册的 Codex 桌面，再验证 codex_app 工具目录及只读会话查询。此发现流程不生成或猜测管道，不发起任务、不更换已选目标、不伪造来源。通道在桌面重启期间保持运行并等待恢复。不要因为恢复连接而重发结果未知的操作；仅连接建立前失败的请求可以在新连接上首次提交。连接状态由定期实际查询确认。其他平台仍依赖宿主刷新绑定。
